# 当前有效决策

## 页面命名与产品映射

- 决策：首页为总入口；观山对应 VisonCube-TV；听雨对应 VisonCube-Music；逐风对应 VisonCube-AI。
- 原因：用户已明确确定这套命名。
- 影响：导航、路由、文档和界面必须统一使用，不得改回通用“产品一/二/三”名称。

## 视觉方向采用 Raycast 风格借鉴

- 决策：借鉴 Raycast 的深色层级、克制边框、紧凑导航、强标题和真实产品演示区。
- 原因：用户明确认可该参考界面。
- 影响：官网使用深色优先的品牌视觉，保留 VisonCube 自己的山、雨、风主题，但不展示软件图标。
- 约束：不得复制 Raycast 的品牌色、Logo、英文文案、键盘视觉或具体页面结构。

## 先原型确认再正式开发

- 决策：先交付文档和桌面/手机截图，用户确认后再搭建正式前端工程。
- 原因：降低整站完成后再返工的风险。
- 约束：当前 `prototype/` 只用于视觉确认，不视为生产实现。

## 未登录状态隐藏产品导航

- 决策：网站未登录时顶部只显示 `VisonCube`，不显示首页、观山、听雨、逐风；登录成功后才进入产品主界面。
- 原因：用户明确要求网站与客户端保持登录门禁逻辑。
- 影响：正式路由需要会话恢复和全局导航守卫；访客入口直接展示统一账户登录。
- 约束：前端隐藏不能代替服务端鉴权，受保护数据接口仍必须验证 Session。

## 网站只使用产品名称，不展示软件图标

- 决策：网站界面只使用 VisonCube、观山、听雨、逐风名称和固定色彩/抽象状态，不显示现有软件图标或软件截图。
- 原因：软件图片会随版本调整，不应让网站视觉依赖短期素材。
- 影响：登录品牌区采用纯文字品牌场，产品舞台以名称和抽象图形区分产品。
- 约束：以后增加页面时不得重新引用客户端图标作为网站标识。

## 登录前后界面采用统一产品级视觉规范

- 决策：大面板、产品卡片和交互控件分别使用 24px、16px、10px 圆角基线；登录后首页采用工作台式引导，产品舞台直接承担产品映射，不再显示重复索引、静态伪在线状态和无意义编号。
- 原因：减少宣传落地页和仿窗口装饰感，让登录前后的信息层级、交互状态和移动端密度保持一致。
- 影响：正式工程需要沿用当前语义色、间距、圆角、focus-visible、active 和 44px 手机触控基线。
- 约束：视觉状态不得伪装成真实后端状态；未接入 API 时只展示静态产品信息。

## 产品页使用统一发布客户端编号

- 决策：观山使用 `tv-android`，听雨使用 `music-android` 与 `music-windows`，逐风使用 `ai-windows`；正式网站统一请求 `/api/releases/{client_id}`。
- 原因：服务器发布清单负责安装包文件名和下载地址，网站更新时不需要修改固定链接。
- 影响：产品页只显示 `display_version`、平台、安装包类型和发布时间，下载按钮使用响应中的 `download_url`。
- 约束：首页不堆放安装包；发布接口保持公开但产品页面受登录门禁保护；未配置 AI 发布包时显示暂未提供。

## 正式网站采用 Vue 3 + TypeScript + Vite

- 决策：正式网站使用 Vue 3、TypeScript、Vite 和 Vue Router，API、认证状态、路由、布局、页面与组件分层存放。
- 原因：沿用已确认的 Web 技术方向，保持静态部署体积小，并避免将业务逻辑集中在入口组件。
- 影响：正式实现位于 `src/`，无依赖原型继续保留用于历史视觉参考。
- 约束：第一阶段不引入 Pinia、Axios、UI 组件库或 React 依赖。

## Web 会话使用 sessionStorage 和 Bearer Token

- 决策：网站保存后端返回的 Bearer Session 到 `sessionStorage`，启动时调用 `/api/auth/me` 恢复并校验。
- 原因：现有后端只支持 Bearer Token；第一阶段避免长期 localStorage 会话，也不扩大范围改造 HttpOnly Cookie 与 CSRF。
- 影响：刷新页面可以保持登录，关闭浏览器标签后需要重新登录；服务端 401 会清除会话。
- 约束：前端不保存密码、验证码、SMTP 授权码或服务端密钥。

## Web 以邮箱验证状态作为产品区门禁

- 决策：只有存在邮箱且 `email_verified_at` 有值的账户才能进入首页、产品页和账户页；注册后、历史未绑定邮箱账户和未验证账户进入邮箱验证页。
- 原因：现有 Android 客户端已采用同一门禁，后端注册接口会先建立会话再完成邮箱验证。
- 影响：邮箱验证码登录和找回密码成功后可以直接进入产品区；自定义客户端仍可绕过前端门禁，后端强制验证属于后续安全加固范围。
- 约束：不在本阶段改变后端数据库或认证接口。

## 发布接口缺少公开版本时不显示内部版本

- 决策：若发布响应没有 `display_version`，网站显示“当前版本待确认”，不回退显示内部 `version`。
- 原因：线上旧清单仍返回内部版本号，普通用户不应看到内部构建版本；网站仍可使用有效的 `download_url`。
- 影响：线上清单补齐 `display_version` 后无需修改网站即可显示公开版本。
- 约束：网站不在源码中写死安装包地址或公开版本号。
